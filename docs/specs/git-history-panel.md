# Spec：Git 历史面板（多仓库只读浏览）

状态：待实现　|　日期：2026-09-23　|　来源：多仓库工作区浏览需求（对标 IntelliJ IDEA 的多 VCS root 管理，只读子集）

## 问题陈述

开发者的一个工作区目录下往往有多个 git 仓库：外层目录本身是仓库、内层的每个服务目录各自也是独立仓库（嵌套仓库，通常被外层 `.gitignore` 忽略）；或者外层只是普通文件夹、内层若干目录各自是仓库。

pi-web 目前只能查看"会话目录所属那一个仓库"的未提交变更与 diff：换一个仓库就要新开会话；提交历史则完全看不到，必须自己开终端敲 `git log`。嵌套仓库因为被外层 ignore，在外层会话里甚至感知不到它们的存在。

## 解决方案

新增一个**只读**的 Git 面板，以右侧栏独立标签的形式存在：

1. 自动扫描会话目录下（含目录自身）的所有 git 仓库——包括被 `.gitignore` 忽略的嵌套仓库
2. 通过下拉框（select）切换仓库
3. 查看选中仓库的提交历史（log）
4. 点击某次提交，查看该提交改动的文件列表
5. 点击其中的文件，查看该文件在此提交中的 diff

左侧文件浏览器新增一个图标按钮作为入口。Git 标签与文件标签完全独立：左侧浏览文件、查看现有 diff 的所有行为不受影响。

## 实现决策

### 仓库发现

- 从会话 cwd 出发做**受限深度文件系统扫描**（深度 3 层，覆盖"工作区 → 服务分组 → 服务仓库"与"文件夹 → 仓库"两类真实结构）；目录含 `.git`（目录或文件，兼容 worktree）即判定为仓库。仓库目录**继续下钻**——外层仓库包裹服务仓库是核心场景，不下钻会遮蔽全部嵌套仓库；成本由深度上限与目录总数上限控制。
- 跳过隐藏目录（`.` 开头）与通用重目录黑名单（node_modules、.next、dist、build、__pycache__ 等，语义对齐文件索引接口已有的忽略名单）；扫描目录总数设上限兜底。
- 扫描结果带 TTL 缓存与并发去重（模式沿用项目缓存的既有实践）；提供显式刷新入口。
- cwd 自身是仓库时排第一；cwd 不是仓库时照常扫描子目录。
- 产出：仓库根绝对路径、目录名、相对 cwd 的显示路径、当前分支。

### API（全部只读，均为 GET）

| 接口 | 参数 | 返回 |
|---|---|---|
| 仓库列表 | `cwd` | `{ repositories: [{ repositoryRoot, name, relativePath, branch }], scannedAt }` |
| 提交历史 | `repo`, `limit`(默认 20), `offset` | `{ commits: [{ hash, shortHash, author, timestamp, subject }], hasMore }` |
| 提交详情（不带 path） | `repo`, `hash` | `{ files: [{ path, status(M/A/D/R…), previousPath? }] }` |
| 提交详情（带 path） | `repo`, `hash`, `path` | `{ patch }`（该文件在此提交中的 unified diff） |

- 四个接口全部走与现有文件访问相同的 allowed-roots 白名单校验（cwd 必须在允许根内，repo 必须位于 cwd 子树内）。
- git 子进程调用对齐现有模式：`LC_ALL=C` 固定、10s 超时、maxBuffer 上限；单仓库失败返回该仓库的 error 字段或该请求的错误，不影响其他仓库。
- 现有的变更状态与 diff 接口**不做任何改动**。

### 前端

- 右侧栏新增**常驻 Git 标签**（标签条已有非文件类标签的先例：终端标签）。
- `GitPanel` 组件：仓库 select → 提交 log 列表 → 提交文件列表 → 单文件 diff，**单栏推入式导航**（详情替换列表，带返回）；推入层级：仓库切换即重置到 log 层。
- 左侧文件浏览器头部新增图标按钮：打开右侧栏并切到 Git 标签。
- Git 标签默认选中 cwd 所属仓库（cwd 是仓库时），否则选扫描列表第一项。
- 所有文案走现有 i18n 机制（参考 docs/i18n.md）。

### 移动端布局（重点）

- 断点沿用全局约定：≤640px 为移动端（isMobile），≤480px 为窄屏（narrowMobile）；不新增断点。
- **移动端右侧栏即全屏层**（现有行为：移动端无全宽展开模式）：Git 面板占满整屏，单栏布局，无左右分栏。
- **单栏推入式导航**（移动端唯一形态）：`仓库 select → 提交 log → 提交文件列表 → diff` 逐级推入，每级顶部有返回按钮；切仓库重置到 log 层。桌面端默认右栏宽度下用同一形态；仅桌面全宽展开时改为上下分区同屏（列表在上、diff 在下）。
- 触控目标：列表行高与按钮高度不小于现有移动端控件标准（≥36px，与标签条高度一致），下拉框与刷新按钮在窄屏（≤480px）占满行宽、统计信息收缩。
- diff 视图：等宽字体、`pre` 横向滚动，禁止折行截断；文件路径标题在窄屏可换行。
- 返回导航需支持系统级返回习惯：面板内逐级返回按钮；不做手势路由（避免与浏览器/PWA 返回冲突）。

## 测试决策

- 只测外部行为：给定目录树 fixture → 仓库发现的输出列表；给定临时 git 仓库 fixture（用脚本真实初始化并提交）→ 各 API 返回的 JSON 形状；组件测试断言渲染结果与导航状态迁移，不断言内部实现。
- 覆盖模块：仓库发现逻辑（临时目录 fixture：嵌套仓库、被 ignore 仓库、非仓库 cwd、黑名单目录、深度边界）；四个 API 路由（含 allowed-roots 拒绝、单仓库失败隔离）；GitPanel（渲染 + 推入/返回导航 + 移动端单栏形态断言）。
- Prior art：`lib` 下的 `*.test.mjs` 纯函数单测（node:test + 临时 fixture）；`components` 下的源码断言 + vm 沙箱测试（如 AppShell 移动工具栏、BranchNavigator 的既有测试）。

## 范围外

- 一切写操作：commit、stage、push/pull、revert、checkout 等
- 跨仓库聚合的未提交变更列表、跨仓库合并提交时间线
- 分支拓扑图（graph）、提交搜索、blame、单文件历史（`git log -p <file>`）
- 手动配置仓库映射（IDEA 式 Directory Mappings）
- 仓库内仓库的再嵌套扫描（深度超过 3 层的仓库不发现）
- 现有单仓库变更区块、文件树徽标、FileViewer 的任何改造
